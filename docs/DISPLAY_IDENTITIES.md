# 虚拟屏身份与 ColorSync 维护

## 身份与回收规则

主应用使用两组固定的 `vendorID/productID/serialNum`：`0x5555/0x0001/0x55550001` 与 `0x5555/0x0001/0x55550002`。
首次使用前写入 `~/Library/Application Support/UUDisplay/display-identities.json`；重启或文件丢失时仍使用同一组序列号。文件损坏、版本不兼容或保存失败会停止建屏并记录原因。

虚拟屏统一显示为“UUyc companion”，尺寸与 HiDPI 仍按设备配置设置。正常重连优先复用第一个空闲槽位；更换尺寸时允许新旧两块屏短暂重叠。执行器先等新屏上线、设为主屏并安全回收旧屏，再处理最新的配置变化。创建、应用模式或设主屏失败时保留健康的旧屏，新对象经过存活期保护后回收。

释放对象后，槽位继续保留，直到在线列表确认对应显示器已离线。其他进程占用的槽位不能借用；槽位不足时等待，显示器查询失败时也停止建屏。手动恢复物理屏优先处理，不会被槽位等待挡住。

该机制约束主应用生成的序列号数量；ColorSync/WindowServer 的持久记录行为仍需在目标 macOS 上实测。历史随机身份不会因为升级自动消失。

## 显示配置超时与恢复

配置事务返回 `cannotComplete` 或 `1014` 时，应用暂停建屏、删屏和布局调整，并优先尝试恢复物理屏。菜单显示“屏幕调整已暂停，正在等待系统恢复”。失败的物理屏恢复会延长重试间隔，手动恢复和断开可立即再次尝试。

30 秒后在后台队列提交当前显示器的原点，检查实际配置服务是否响应。查询显示器列表成功或空事务成功不能单独证明服务恢复。检查失败时逐步延长间隔，最长 5 分钟；连续两次检查成功、间隔至少 5 秒后，才解除保护，先收尾残留显示对象和布局，再应用最新连接配置。等待期间更改设备、暂停或断开的目标仍会保留，退出不需要等待下一次健康检查。手动恢复后需要更早检查时，原有的长等待计时会失效。

检查成功不保证后续真正切屏也会成功。自动恢复后再次超时的连续故障，最多恢复两轮；此后停止自动调整，菜单提示退出并重新打开应用，物理屏兜底恢复仍保留。只有完整显示流程收敛后才清零连续故障计数，避免“检查成功、切屏失败”持续循环。自动收尾和重新建屏可能让远程画面短暂中断；这一路径尚未通过人为制造故障的实机验证。

布局还原只提交原点确实变化的在线显示器，避免在系统已经自动还原时增加事务。还原成功后才删除 `session.json`；失败记录保留，供后续重试或下次启动恢复。开始、配置原点和提交事务阶段的错误均保留原始错误码。

这些措施避免短暂超时后永久停用，也减少冗余事务；无法保证 macOS 私有显示服务不再超时。持续失败且无法自行恢复时，仍可能需要注销或重启 Mac。自动恢复路径使用模拟 API 回归测试，不以反复切换真实显示器制造故障。

## 远程声音重连兼容流程

针对上游 [issue #16](https://github.com/aoyamashou/UUyc-companion/issues/16)：关闭实体屏后 UU 可能只恢复视频采集，保留同一虚拟屏再重新建立会话可作为兼容恢复。本实现不修改 UU 的音频采集流、音频输出设备或本地静音设置。菜单栏或被控端设置中的“恢复远程声音”可随时打开查看；只有远程已连接、当前虚拟屏在线稳定且物理屏已软关闭时才能开始计时。

恢复入口打开非模态状态窗口，显示当前采集检测和三步指引；查看、重复打开或刷新不会开始计时。点击“开始 15 秒重连”后窗口保持打开，成功后才在 `~/Library/Application Support/UUDisplay/audio-reconnect.json` 保存版本、主程序 PID、显示器 ID、系统运行时间与固定截止时间。等待为 15 秒，重复点击或断开不续期。窗口模型每 0.5 秒更新倒计时与步骤，重连完成或超时后保留结果。关闭窗口或停止本次恢复会取消等待。连接监测仍使用原有 1.5 秒防抖；真正断开后保留同一显示对象，匹配原显示器 ID、尺寸和 HiDPI 的重连清除等待；不同配置、未知设备或外部恢复物理屏时取消保留。

窗口不阻塞主线程，心跳和连接监测仍在 common run-loop modes 中运行。界面提示断开、重连、等待设备识别、播放音频确认或超时；名称刷新不会清除完成提示。

恢复窗口提供用户主动触发的四秒测试提示音，使用 AVAudioPlayer 播放内置生成的双声道 PCM WAV。播放跟随当前系统输出，不修改设备或系统音量；不循环，不自动播放。窗口关闭、远程断开或开始重连时停止播放，完成回调通过播放代次和播放器身份拒绝旧结果。播放状态与采集检测独立，播放完成不代表控制端已听到声音。

音频检测在串行后台队列读取 /usr/bin/log show --style ndjson 的 UU SCStream 创建、输出注册/移除、启停记录，仅虚拟屏远程时每 5 秒更新。单次查询以 4 秒和 1 MiB 为上限，超限结束查询并显示无法判断；不录音、不创建 AudioTap、不改输出设备或静音状态。流指针复用、进程/启动 UUID 变化、重叠查询和会话变化均独立处理，旧查询结果不能污染新会话。私有 AudioTap 不可见、没有音乐和控制端实际静音不作为故障证据。启动时已存在的会话最多回看一小时；后续新会话限制到本次连接附近，证据不足保留未知状态。

手动恢复、暂停、关闭物理屏软关闭、配置变化、显示保护状态和退出取消窗口。到期回调通过代次失效，避免旧计时器影响之后的会话。写盘失败不延迟正常断开；旧进程记录不恢复成新进程的待重连状态。

守护助手只为有效版本、当前心跳 PID、仍在线的伴侣显示器和未过期记录豁免断开恢复。超出 15 秒、损坏记录、显示器离线、PID 不匹配均不豁免；主程序退出或心跳超时先于所有豁免。守护助手仍按原 5 秒间隔检查。

`scripts/test-connection.sh` 编译实际 `Coordinator` 与窗口/守护决策类，替代 UU、显示器及用户配置；覆盖普通断开、原对象重连、名称刷新、15 秒边界、未断开、设备变化、未知名称、识别超时、手动取消、外部恢复、显示保护、写盘失败、旧回调及守护优先级。Python 测试覆盖异步断开、其他连接保留、未知结构拒绝和超时后不连接。UI 可用 `UUDisplay --render-settings <临时目录>` 生成截图；渲染路径跳过心跳与全局快捷键，避免影响现有实例。

实机验收需要保持“被控端静音”，点击恢复并断开重连，对比显示器 ID 未变、物理屏未重新上线，并从控制端实际确认声音；分别验证 Mac、手机、窗口超时、手动取消和守护助手。辅助脚本在控制端运行，未知 CLI 状态格式会拒绝操作。本次构建和模拟测试不构成实机声音恢复验证，没有在当前主机断开实际会话或制造故障。

## 回归测试与实际验证

运行 `scripts/test-connection.sh`。除连接检测外，还覆盖 1000 轮身份分配、30 轮显示执行器重连/快速改尺寸、构造/模式/配置事务失败、未上线超时、延迟撤销、外部槽位占用及手动恢复。私有 API 使用模拟模块，测试不会改变真实屏幕。缓存维护使用临时文件测试备份、选择规则、冲突拒绝与回退。

轻量实机验证需要先完全退出主应用与探测工具，保存工作，再显式运行：

```sh
zsh scripts/test-display-identities.sh --real-displays
```

该脚本保持物理屏在线，不执行主屏或布局配置事务，创建两个槽位并各复用一次，对比不同尺寸/HiDPI 下的 UUID，检查安全撤销与原主屏。2026-11-16 在本机 macOS 27、Swift 6.4 上四次创建验证通过；这项检查与完整应用的反复切屏压测范围不同。

在目标机器验证时先保存工作，关闭“远程时只保留虚拟屏”以保留物理屏，再进行少量实际连接、重连和尺寸变更。每次上线执行：

```sh
swift scripts/display-snapshot.swift
```

确认主应用在线序列号只来自上述两组，同一槽位的 UUID 可复用，断开完成后虚拟屏离线。分别在测试前、测试后和再次重连后执行缓存审计，核对 UUID 记录数量没有持续增长，并检查颜色服务响应：

```sh
sudo python3 scripts/colorsync-maintenance.py audit
python3 scripts/colorsync-maintenance.py healthcheck --timeout 10
```

`healthcheck` 在独立子进程查询 ColorSync，超时会终止子进程并报告失败，避免把同步等待放进应用主线程。它包括 Swift 脚本启动时间，不能单独用于精确性能基准。

## 旧版本记录迁移

维护工具只识别标准缓存 `/Library/Caches/ColorSync/com.apple.colorsync.devices` 中的显示器记录。所有本地化名称必须属于“UUyc companion”或旧名称“UUDisplay”，ICC 路径必须对应同名、同 UUID 的显示器文件，记录必须离线，且所有引用文件均缺失。现存文件、权限不明、未知结构、自定义路径和其他显示器记录均保留。

先断开远程并完全退出应用、探测工具，再生成预览。输出目录必须尚不存在：

```sh
sudo python3 scripts/colorsync-maintenance.py prepare --output /private/tmp/uuyc-colorsync-plan
```

目录包含原始 `backup.plist`、候选 `cleaned.plist` 和列明删除项及校验和的 `manifest.json`。此命令只生成文件，系统缓存保持原样。

核对预览后，停止当前用户的颜色代理并明确应用：

```sh
killall colorsync.useragent
sudo python3 scripts/colorsync-maintenance.py apply --plan /private/tmp/uuyc-colorsync-plan
```

工具再次检查在线显示器、代理进程、ICC 文件和原缓存；缓存变化或代理已重启会拒绝写入。采用原所有者和权限原子替换，只删除预览列出的记录，不更改 WindowServer 配置，也不自动重启服务或应用。应用后重新打开活动监视器，并运行审计和 `healthcheck`。

需要回退时，同样先退出应用并停止颜色代理：

```sh
sudo python3 scripts/colorsync-maintenance.py rollback --plan /private/tmp/uuyc-colorsync-plan
```

仅当当前缓存与清理后文件仍完全一致时才恢复原始备份；出现新系统记录会拒绝覆盖。备份须保留到验证结束。维护涉及系统私有缓存格式；目标系统结构变化时应重新分析，不能扩大删除范围绕过检查。
